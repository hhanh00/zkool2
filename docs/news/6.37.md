---
title: Since 6.36
---

The 6.37 release brings the lower transaction fee of ZIP 2009, a backup
view for every account whatever key created it, and a network choice when
you create a database.

*Released 12 November 2026 as [6.37.0](https://github.com/hhanh00/zkool2/releases/tag/zkool-v6.37.0).*

## Lower fees

Zkool now prices a transaction at 1,000 zatoshis per logical action from the
ZIP 2009 activation height (3,590,000 on Mainnet, 4,465,026 on Testnet), and
at 5,000 before it. The ZSA chain stays at 5,000, since its node predates the
reduction. The fees shown on the send page, the dust limits and the help
texts follow the same value.

A new "Fee per action (zatoshis)" setting replaces the schedule when you set
it. Leave it empty to use the automatic value. See
[Payments](../guide/pay.md).

A note that the migration padded under the old fee no longer matches a
denomination under the new one, so the migration splits it once more.

## Back up any account

The key icon on the Viewing Keys page now appears for every account except
Ledger accounts. Until now it only showed a seed or a FROST backup string, so
an account imported from an xprv, a WIF or a Sapling spending key had no way
to show its key. The backup block now shows the key the account was created
with:

- the seed, with its passphrase and account index,
- else the xprv, the WIF, the Sapling spending key or the FROST backup string,
- for a viewing-only account, the key it was imported from, or a unified
  viewing key when it spans several pools.

The biometric prompt only appears when the key is secret.

A Sapling viewing-key account shows a Sapling-only unified viewing key rather
than the `zxviews` string it was imported from: the import keeps only part of
that key. The unified key imports back to the same account.

A **Show Key Tree** button opens a new page with every key of the account as
a tree: the passphrase and index, the transparent key with one entry per
address, Sapling and Orchard. A switch flips every entry between its secret
key and its viewing key. A viewing-only account opens on its viewing keys and
has no switch. The Orchard spending key is never shown, as it has no
standard encoding; restore it from the seed. See
[Account](../recipe/account.md).

## Choose the network of a new database

The dialog that creates a database has a Network dropdown (Mainnet, Testnet,
Regtest, ZSA Regtest), preselected to the network of the open wallet. The
choice always wins: a wallet created as Mainnet under a name containing
"testnet" used to come out as a testnet wallet. A name that already exists is
refused instead of reopening the first wallet, and the app switches to the
new wallet like one picked from the list. See
[Database](../recipe/database.md).

The default server and explorer now follow the wallet's network.
zecblock replaces cipherscan as the Mainnet explorer, with its testnet site
on Testnet.

## Internal change

- An account imported from a single transparent key (a WIF or a public key)
  no longer uses internal change, and neither do incoming-only and Ledger
  accounts. Their edit page no longer offers to switch it on, and a flag
  such an account already holds is cleared when the wallet opens.
- On a FROST account, the Use Internal Change tooltip reminds you that every
  member must use the same setting: a member with it off does not see the
  change sent to internal addresses. See
  [MultiSig Accounts](../frost/overview.md#internal-change).

## Also

- The addresses page lists the transparent addresses the wallet actually
  watches. A seed account no longer loses some change addresses, a WIF or
  public-key account shows its address, and an account without internal
  change no longer lists change addresses.
- The account page hides the pools whose balance would read 0.000, and
  drops the balance chips when no pool qualifies. Tapping a chip collapses
  them. The send page keeps all four chips, so you can still fill in the
  address of an empty pool.
- Flinging the account list past its end no longer makes the rows vibrate.
- GraphQL: `useInternal` can be left out of `createAccount`, and then
  follows the key; a value the key cannot honor is an error. `editAccount`
  can set it, which lets a FROST member on the daemon match its group. The
  daemon's `--coin` creates a missing wallet for that network, whatever
  its file name.
